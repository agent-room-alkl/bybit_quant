# 项目审查与近两个月交易复盘方案

审查日期：2026-09-27。代码版本：3d6e134。目标实盘窗口：2026-07-27 至数据提取时刻，展示时区 Pacific/Auckland，计算与存储统一 UTC。

> 后续实施状态：见 [v7 优化报告](OPTIMIZATION_V7_CN.md)。本文保留初次审查时点的发现，行号对应原代码。

## 结论与证据边界

项目是以 SOLUSDT 为主的现货网格、趋势跟随混合系统，支持可选杠杆、本地常驻进程和 Vercel 定时任务。策略包含市场状态识别、多指标评分、分批进出、成本参考、BTC 过滤及新闻情绪。

这些设计具有合理动机，但实现存在成交记账、风控接线、策略状态和回测一致性问题。因此，不能仅凭 README、旧优化文档或现有回测收益确认策略有效。

初次审查时缺少运行数据。用户随后更新了 .env，现已成功只读连接数据库和 Bybit，完成近两个月成交与资金流水复盘。实际结果见 `../data/audit_2026-09-27/TRADE_REVIEW_CN.md`；本文件保留代码审查和实施方案。未运行交易程序，未下单，未修改策略。

## 已核实的问题

### P0：把订单受理当成成交

位置：bot_core.py:930 起的下单与记账流程。

`retCode == 0` 后立即计入交易次数、计划交易额和止损事件；记录的是委托数量和委托价格，未在该流程确认实际成交数量。IOC 订单可能部分成交或未成交，导致交易账本与实际资产不一致。失败也更新同方向冷却，可能延迟必要重试。

方案：建立订单与成交两张表；订单受理只更新订单状态，成交以 execId 去重入账，按实际数量、均价、费用更新库存、盈亏和策略状态。重启后补拉成交并对账。错误重试与策略冷却分开。

Bybit 官方明确说明下单确认只表示请求被接受，接口异步，需要另外确认订单状态：https://bybit-exchange.github.io/docs/v5/order/create-order 。成交查询：https://bybit-exchange.github.io/docs/v5/order/execution 。

### P0：日亏损保护缺少有效数据更新

位置：bot_core.py:212、222、355、743；strategy_v5.py:741；main.py:1309。

`_get_daily_pnl` 读取 meta，缺失默认 0；`_update_daily_pnl` 只有定义，仓库内没有调用。页面重置接口会写入 0。5%/24小时熔断在当前策略中表现为 shadow 标记，不能据此认为存在真正持续24小时的执行熔断。

方案：建立账户级净值快照，计入持仓浮盈亏、费用与借款负债，调整充值提现影响。分别定义日初损失与日内高点回撤；触发后持久化恢复时间，禁止增加风险，允许必要减仓。不能把每笔交易的百分比简单相加当成账户日收益。

### P0：保护性卖出仍可能被拦截

位置：bot_core.py:738–823；strategy_v5.py:1250、2177。

止损仍经过同方向冷却、每日次数限制，以及 `should_trade_gate` 的波动率过滤；is_stop_loss 主要豁免均线卖出过滤，没有统一豁免前述限制。策略内部上次止损后60分钟也可能不再产生止损；刚买入30分钟内阈值翻倍。以上行为可能在持续下跌中延迟减仓。

此外，仓位再平衡在浮亏时拒绝卖出（strategy_v5.py:910附近），因此熊市目标仓位不是严格暴露上限。不能将配置的止损百分比理解为账户损失上限。

方案：给信号增加明确的 risk_exit 类型，替代中文原因字符串识别。风险退出绕过普通交易频率、利润门槛和入场波动过滤，保留价格、余额、去重及成交状态检查。把禁止重新买入的冷却与进一步风险减仓分开。

### P0：实盘每拍重建策略，丢失跨周期状态

位置：bot_core.py:655附近；strategy_v5.py:203–227、316；backtest.py:594。

实盘每次调用都 `create_smart_strategy(cfg)`，初始化市场状态、待确认次数、日止损次数、止损价格记忆等。回测则复用一个策略对象。中低置信度需要连续两次确认的 regime 切换在实盘难以累计；部分止损记忆跨拍丢失。传入的 last_stop_loss_time 另有持久化，不能把它与丢失的内部状态混为一谈。

方案：每交易对持久化完整策略状态，成交后更新交易相关状态；本地与 Vercel 共用状态格式和策略版本号。切换配置和重启时执行显式迁移。

### P0：现有回测存在前视偏差和执行口径差异

位置：backtest.py:334、418、594、630、704；trade_logic.py:107。

1. 先聚合完整小时 K 线，再在同一小时的早期15分钟 bar 使用该小时的完整指标，读取了当时尚未产生的信息。
2. 实盘 signal.position_pct 按总资产计算卖出金额，回测 sell() 按已有 SOL 数量的百分比卖出。例如总资产1000、SOL仓位600，减仓20个百分点，实盘卖200，回测卖120。
3. 回测直接执行 strategy.analyze 的信号，没有经过实盘 bot_core 的全部冷却、限次、额度和额外买入过滤。
4. 当前 bar 指标计算后按同一收盘价成交，没有充分模拟下一可成交时点、点差、滑点、IOC 部分成交及实盘最低金额。
5. 新闻情绪来自手工历史事件表，不是当时存档的实时输出，不足以验证新闻模块实盘价值。

方案：只使用决策时刻已收盘的多周期数据；共享下单数量和风控逻辑；下一可成交事件撮合，费用与滑点分开建模；无真实历史情绪时先关闭新闻模块做基线。修复前不引用现有收益率作优化依据。

### P1：成本与历史数据完整性不足

位置：cost.py:10、31、79；db.py:25。

成本函数使用移动加权平均，文档却称 FIFO；买入费以基础币收取时未减少所得基础币数量。仅回溯60天时，窗口之前已有持仓的成本可能缺失。拉取成交某个窗口报错会跳过该窗口并返回其余数据，容易把不完整历史误作完整账本。

本地只保留200条委托记录、500条信号。默认每120秒一个信号，单交易对500条只覆盖约16.7小时；200条委托也无法保证覆盖两个月。Vercel 的 PG 是另一路存储，需分别检查。

方案：追加式保存成交、订单、信号、净值、配置版本及充值提现；历史拉取返回完整性状态，不完整时禁用依赖成本的新增风险决策。引入期初库存及成本，处理费用币种和外部转入。

### P1：时间尺度和风控参数存在名实不符

位置：bot_core.py:365–375、577；cost.py:634；strategy_v5.py:461；trade_logic.py:361。

BTC仅拉100根15分钟K线，约25小时，却传入 calculate_15day_trend(days=15)；数据不足时退回最早样本。结果被标作长期趋势，又用于“BTC日跌”门控，实际既非固定15天，也非严格24小时。

RiskManager 在主循环中被导入但未使用；max_single_trade_pct 没有通过这个管理器限制主循环订单。cooldown_after_loss_min 在 bot_core 中被读取但未用于该处执行检查，策略另用常量。因此修改配置不等于改变实际行为。

方案：明确各字段的周期、单位和已收盘要求；将实际生效配置、策略版本输出至每次决策日志；整合重复风控并检查每个配置参数有实际消费者。

## 近两个月实盘复盘所需数据

最低需要：成交时间、交易对、方向、execId、orderId、成交价、数量、手续费金额及币种；期初与期末余额和持仓成本；期间充值提现、内部划转；若用杠杆，补充借款、利息与负债。识别自动交易需要 orderLinkId 或委托日志关联，避免把手动操作算成策略表现。

判断单笔交易逻辑还需要当时生效的配置/代码版本、信号原因、持仓和行情快照。仅有成交可分析结果，但不能准确还原当时为什么交易。没有期初成本时，跨窗口持仓的已实现收益应标为不可确定。

取得数据后按以下步骤执行：

1. 按UTC切分日期、按 execId 去重并检查缺页；按 orderId 合并部分成交，同时保留原始成交。
2. 重建库存、手续费、已实现和未实现盈亏，与账户余额对账。
3. 报告现金流调整收益、净值最大回撤、成交额/平均净值、总费用及费用占毛收益比例（毛收益非正时单列）、配对后的交易胜率、平均盈亏与 Profit Factor；样本太少则明确不稳定。
4. 与相同期初资产、相同外部现金流的持有不动基准及预先定义的固定仓位基准比较；避免直接拿低仓位策略与全仓SOL风险混比。
5. 逐笔标注下跌加仓、止损后回补、短时反向交易、成本以下风险减仓、卖出后追涨、被拦截的退出和未成交委托；结合当时行情判断合理性。
6. 按牛/熊/震荡、仓位区间和信号类型拆分，报告样本量及收益集中度。连续买入次数按订单计数，避免部分成交被当成多次加仓。

## 优化实施顺序与验收

### 第一阶段：先恢复可审计性和风险闭环

落地成交账本、账户净值熔断、风险退出优先级、跨拍状态持久化。验收用例包括未成交/部分成交IOC、接口超时重试、重启恢复、当日次数耗尽后的止损、价格连续下跌及资金转入转出。余额与交易所对账仅允许精度和结算时间差范围内误差。

### 第二阶段：建立可信回放

修复小时指标前视、卖出比例、费用与实盘门控差异。使用相同配置、同一信号与状态输入核对回放和实盘决策；排除未来数据。此阶段才产生可用于比较的基线回测。

### 第三阶段：做少量可解释策略实验

- 网格只在震荡状态启用；趋势策略使用单独的入场与退出条件，避免旧卖出价永久限制趋势重建仓位。
- 网格间距与ATR、往返真实费用和点差共同决定；尝试少量候选值，不在两个月样本上大规模搜参。
- 使用单次最大损失预算倒推仓位：交易名义金额约等于允许损失金额/止损距离比例，并受总仓位、现金和流动性上限约束。止损不是保证成交价，另做跳空和滑点压力场景。
- 将加仓次数、总风险暴露、状态恶化后的停止加仓联动；采用账户级风险上限。
- 对多指标做消融实验：基础趋势/波动/量能为基线，分别增加RSI、MACD、新闻。保留能在样本外贡献净收益或降低风险的部分，避免多个相关指标重复计票。
- 新闻和ATR自适应退出先保留影子对照，积累真实输出后再评估。

验证采用时间顺序的训练/验证分离及滚动样本外评估，固定最后一段数据不参与选参。两个月用于定位近期问题；稳健性需补充更长且包含不同市场状态的历史。所有候选以扣费、滑点后的收益和回撤比较，并报告邻近参数是否稳定。

### 第四阶段：影子对照与小规模上线

先积累足够信号和退出事件，核对真实成交模拟与实盘差异，再按既定风险预算放量。上线前必须通过数据对账、保护性退出不被普通限次拦截、重启状态一致和无前视回放；策略收益不承诺提升，也不能仅凭短期胜率决定上线。
